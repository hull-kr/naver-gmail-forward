# naver-gmail-forward

네이버 **받은메일함**에 새 메일이 오면 Gmail 로 전달합니다. GitHub Actions 가 5분마다 실행합니다.

- 스팸메일함은 받은메일함과 다른 폴더라서 전달하지 않습니다.
- 메일 내용은 어디에도 저장하지 않습니다. 메모리에서 읽어 바로 보내고 끝납니다.
  남기는 것은 "어디까지 보냈는지"를 뜻하는 메일 번호(IMAP UID)와 실패 횟수뿐이며, 저장소가 아닌 Actions 캐시에 둡니다.
- 실행 기록(로그)에는 제목·보낸 사람·본문을 찍지 않고 메일 번호와 개수만 남깁니다. 공개 저장소라 로그가 누구에게나 보이기 때문입니다.
- 네이버 쪽 메일은 읽음 표시도 바뀌지 않습니다(읽기 전용으로 열고 `BODY.PEEK` 로 가져옵니다).
- 외부 패키지 없이 파이썬 표준 라이브러리만 씁니다.

## 설정

### 1. 네이버 메일

1. 네이버 메일 → 환경설정 → **POP3/IMAP 설정** → IMAP/SMTP 설정에서 **사용함**
2. 네이버 → 내정보 → 보안설정 → **2단계 인증** 을 켜고 **애플리케이션 비밀번호** 를 하나 만듭니다.

### 2. GitHub Secrets

저장소 → Settings → Secrets and variables → Actions → **New repository secret**

| 이름 | 값 |
| --- | --- |
| `NAVER_USERNAME` | 네이버 아이디 (`@naver.com` 은 붙여도 되고 빼도 됩니다) |
| `NAVER_APPLICATION_PASSWORD` | 위에서 만든 애플리케이션 비밀번호 |
| `GMAIL_ADDRESS` | 받을 Gmail 주소 |

### 3. 첫 실행

Actions → **네이버 메일을 Gmail 로 전달** → **Run workflow** 로 한 번 실행합니다.
첫 실행은 지금 받은메일함에 있는 메일은 보내지 않고 **기준점만 잡습니다.** 그 뒤에 도착한 메일부터 전달됩니다.

## 전달된 메일의 모습

네이버 SMTP 는 로그인한 계정 주소로만 보낼 수 있습니다. 그래서

- 보낸 사람: `홍길동 (네이버 메일 전달) <내아이디@naver.com>`
- 회신 주소(Reply-To): 원래 보낸 사람 → Gmail 에서 **답장** 을 누르면 원래 보낸 사람에게 갑니다.
- 제목·본문·첨부는 원본 그대로입니다.

## 실패했을 때

- 한 메일의 전달이 실패하면 그 자리에서 멈추고, 다음 실행에서 그 메일부터 다시 시도합니다.
- 같은 메일이 **3번 연속** 실패하면(첨부가 너무 큰 경우 등) 그 메일은 건너뛰고 다음 메일로 넘어갑니다.
- 실패가 있었던 실행은 빨간색(실패)으로 끝나므로 GitHub 가 실패 알림 메일을 보내 줍니다.

## 알아 둘 점

- **5분은 최소 간격입니다.** GitHub 가 붐비면 실행이 몇 분에서 수십 분 늦어질 수 있습니다.
- **공개 저장소에 60일 동안 커밋이 없으면 GitHub 가 예약 실행을 멈춥니다.** 멈추면 Actions 화면에서 다시 켜거나 아무 커밋이나 하나 올리면 됩니다.
- Actions 캐시가 지워지면(7일 넘게 실행이 없었을 때 등) 첫 실행처럼 기준점을 다시 잡습니다. 그 사이 도착한 메일은 전달되지 않을 수 있지만 중복 전달은 생기지 않습니다.
